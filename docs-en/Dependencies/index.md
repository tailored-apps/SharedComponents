## How the automated bump works

The workflow runs every Monday at 06:00 UTC (and on demand via *workflow dispatch*). It executes
`scripts/Bump-Deps.ps1`, which walks every `*.csproj` and queries nuget.org for the latest stable
version of each `PackageReference`.

| Rule | Behaviour |
|---|---|
| Wildcard versions (`10.*`, `2.*`) | left alone — they self-update on `restore` |
| Pre-release versions | ignored |
| Latest version's license outside the allowlist (`MIT`, `Apache-2.0`) | **SKIP** |
| License differs between the pinned and the latest version | **SKIP** (relicensing guard) |
| No declared SPDX license | **SKIP** (unless `-AllowUndeclaredLicense`) |
| Package on the `-Ignore` list (e.g. `MediatR` >= 13.0.0, RPL-1.5) | clamped to the highest version below the ceiling |

After bumping, the workflow builds the whole solution (`dotnet build`), generates the entry on this
page, and only then opens a PR labelled `dependencies` and `automated`.

### Running it locally

```bash
# preview without touching any file
pwsh ./scripts/Bump-Deps.ps1 -DryRun -RecordsPath ./bump-records.json

# generate the documentation entry from the report
pwsh ./scripts/New-BumpDocs.ps1 -RecordsPath ./bump-records.json
```
