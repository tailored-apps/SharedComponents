# TailoredApps.Shared.Payments.Provider.Przelewy24

Przelewy24 is an online payment operator (bank transfers, BLIK, cards). This package plugs the Przelewy24 REST API into
`TailoredApps.Shared.Payments`: it registers a transaction and returns the address of the payment page, verifies the
notification Przelewy24 sends, and confirms the transaction with Przelewy24 (`transaction/verify`). It does not query
Przelewy24 for the status of a payment.

## Installation

```bash
dotnet add package TailoredApps.Shared.Payments.Provider.Przelewy24   # brings TailoredApps.Shared.Payments with it
```

## Registration

```csharp
using TailoredApps.Shared.Payments;
using TailoredApps.Shared.Payments.Provider.Przelewy24;

builder.Services.AddPayments().RegisterPrzelewy24Provider();
```

The call registers the provider with its dependencies and adds it to `IPaymentService`. Several providers chain:
`.AddPayments().RegisterPrzelewy24Provider().RegisterTpayProvider()`.

## Configuration

Options are bound from the `Payments:Providers:Przelewy24` section (`Przelewy24ServiceOptions`).

```json
{
  "Payments": {
    "Providers": {
      "Przelewy24": {
        "MerchantId": 12345,
        "PosId": 12345,
        "ApiKey": "<p24-api-key>",
        "CrcKey": "<p24-crc-key>",
        "ServiceUrl": "https://secure.przelewy24.pl",
        "ReturnUrl": "https://shop.example/payment/return",
        "NotifyUrl": "https://shop.example/webhooks/przelewy24"
      }
    }
  }
}
```

| Key | Required | Meaning | Default |
| --- | --- | --- | --- |
| `MerchantId` | yes (greater than 0) | Merchant identifier (a number) | `0` |
| `PosId` | yes (greater than 0) | Point-of-sale identifier (a number); also the user name of the API calls | `0` |
| `ApiKey` | yes | Password of the API calls (HTTP Basic, `PosId:ApiKey`) | - |
| `CrcKey` | yes | CRC key: signs the requests and verifies notifications | - |
| `ServiceUrl` | no | Base URL of the API and of the payment page | `https://secure.przelewy24.pl` |
| `ReturnUrl` | no | Sent as `urlReturn` | empty |
| `NotifyUrl` | no | Sent as `urlStatus`; the address notifications are posted to | empty |

A required key that is missing stops the host at startup with `OptionsValidationException`. The other keys are not validated.

## Usage

```csharp
// payments is an injected IPaymentService
var response = await payments.RegisterPayment(new PaymentRequest("Przelewy24", 49.99m, "PLN")
{
    Title = "Order 7",
    Email = "buyer@example.com",
}, cancellationToken);

// keep response.PaymentUniqueId (the session id) with the order: the notification identifies the payment by it
return Redirect(response.RedirectUrl);   // {ServiceUrl}/trnRequest/{token}
```

## Webhooks

Przelewy24 posts a JSON body; there is no signature header. The `sign` field of the body must equal the hex SHA-384 of the JSON
`{"merchantId","posId","sessionId","amount","originAmount","currency","orderId","methodId","statement","crc"}` built from the
notification's own values in that order, with `CrcKey` as `crc` (compared in constant time). An authentic notification is then
confirmed with `PUT {ServiceUrl}/api/v1/transaction/verify` before a result is returned.

```csharp
using var reader = new StreamReader(Request.Body, Encoding.UTF8);
var body = await reader.ReadToEndAsync(cancellationToken);   // raw body, not [FromBody]
var result = await payments.HandleWebhookAsync("Przelewy24", new PaymentWebhookRequest { Body = body }, cancellationToken);
return result is PaymentWebhookRejected ? BadRequest() : Ok();
```

| Outcome | Result |
| --- | --- |
| verification accepted by Przelewy24 | `PaymentWebhookProcessed`, `Payment.PaymentStatus` = `Finished` |
| verification refused by Przelewy24 (4xx) | `PaymentWebhookProcessed`, `Payment.PaymentStatus` = `Rejected` |
| verification answered with 5xx, 408 or 429, or the body could not be processed | `PaymentWebhookRejected` (`ProcessingFailed`) |
| `sessionId`, `amount`, `currency` or `orderId` missing | `PaymentWebhookRejected` (`MalformedPayload`) |
| `sign` missing or wrong, or `CrcKey` not configured | `PaymentWebhookRejected` (`InvalidSignature`) |

`Payment.PaymentUniqueId` is the `sessionId`. Answer a rejected result with a status outside 2xx: Przelewy24 then sends the
notification again. This provider never returns `PaymentWebhookIgnored`.

## Good to know

- `GetStatus` makes no call to Przelewy24 and always returns `Processing`. The outcome of a payment comes only from the webhook.
- The session id is generated by the provider and returned as `PaymentUniqueId`; `PaymentRequest.AdditionalData` is not sent.
- `RegisterPayment` throws `PaymentGatewayException` (derives from `HttpRequestException`) when Przelewy24 answers with 5xx, 408
  or 429: the state of the payment is not known. An answer without a token returns `Rejected`, with the answer of a failed call
  in `ResponseObject`.
- The amount is sent in the minor unit (amount x 100). `GetChannels` returns a fixed list (`online_transfer`, `blik`, `card`);
  `PaymentRequest.PaymentChannel` is not sent to Przelewy24.
- Requests go through the named HTTP client `Przelewy24` from `IHttpClientFactory`.
